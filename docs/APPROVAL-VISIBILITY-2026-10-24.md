# 审批卡动态可见性验收（2026-10-24）

## 问题与修复

会话和工具轨迹显示“等待审批”，审批卡及按钮已经进入原生无障碍树，但窗口中没有卡片。调整窗口大小后卡片出现，恢复原尺寸后仍然可见。

系统 WKWebView 对 `.composer-wrap:has(> .chat-composer-context:empty)` 的零高网格分支没有在异步插入审批内容后正确更新。修复移除该分支及内容区的 `:empty` 隐藏规则，使用 `minmax(0, 1fr)` 随内容计算高度。空内容自然为零高，长内容继续内部滚动。

## 原生对照验收

- 在实际运行的 Tauri 窗口确认：卡片存在于无障碍树但截图中不可见；窗口缩放一次后恢复显示。没有替用户批准或拒绝该请求。
- 将同一套 React 测试界面放入系统 WKWebView 原生窗口，使用合成审批数据。
- 旧 CSS：从无审批切换为有审批，无障碍树出现卡片和按钮，截图仍然没有卡片。
- 修复 CSS：审批到达后立即可见，无需缩放窗口；移除后再次到达、打开右侧工作区后的窄聊天区均正常。

## 自动化验证与边界

`composer-layout.test.mjs` 默认使用 Chromium；`UI_TEST_ENGINE=webkit` 可使用 Playwright WebKit，浏览器安装位置可通过 `UI_TEST_BROWSERS_PATH` 指定。`UI_REVIEW_OUTPUT` 输出截图及可供原生窗口加载的合成界面 JS/CSS。

回归覆盖审批、问答和计划卡从空内容动态出现、移除及再次出现，审批按钮的实际命中、草稿保留，以及浏览器、终端和窄窗口组合。

Playwright WebKit 未复现旧 CSS 的上述系统 WKWebView 缺陷，不能替代 macOS 原生可见性验收。验收时应直接观察卡片出现，不能先通过调整窗口或读取几何信息触发重排再判断。

本次仅修改前端布局与测试，未修改审批权限或 Runtime。macOS 桌面包已生成；Windows/Linux 未做真机验收。
