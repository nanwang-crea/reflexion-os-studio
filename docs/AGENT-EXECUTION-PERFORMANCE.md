# Agent 执行效率

本次优化保持 Runtime 权限与 Rust 文件边界，不引入 Node 直接读写工作区的路径。

## 执行边界

- 无依赖的文件读取和编辑尽量在同一模型轮声明。单文件用 edits 合并修改；多文件用 file.edit_batch，一批最多 16 个不同文件。
- file.edit_batch 是 Runtime 编排入口，展开为逐文件 file.edit；每个文件独立经过当前权限、精确路径审批、Rust grant、revision 校验和 canonical ToolOutput。不是跨文件事务；每个子调用结束即持久化父级 canonical 进度，取消/重启保留已完成输出；完整子结果保存在 canonical data，模型只接收状态与有界失败提示，避免反复回填 before/after 全文；返回每项成功、失败或未执行状态，禁止重放已完成项目。工具预算计入批量编排入口与展开后的每个实际调用。
- 写入调度只对声明可并发的单文件操作启用按路径互斥。Shell、移动、删除、目录和未知副作用仍为全局屏障；不根据模型声称的安全性放开并发。路径按平台规范化，祖先/子路径视为冲突。资源键不是实际文件身份；符号链接别名仍依赖 Rust 顺序文件分发与 revision 校验，不能据此宣称多文件事务。
- Responses 与 Anthropic 模型流中仅对协议明确结束的只读调用提前执行；Chat Completions 没有独立调用关闭事件，维持完整响应后的整批准入；不以 JSON 恰好可解析判定参数结束。提前读取按独立闭合调用准入预算，最终批次只计剩余调用；重试废弃的读取也占实际预算。需保持工具授权、取消、失败审计和最终工具结果配对，前序写入或未知调用阻止后续只读调用提前执行。

## 耗时观测

Run 记录模型墙钟耗时、物理请求次数、首数据等待、审批等待、写锁等待、工具执行累计时间、工具批次墙钟时间及失败计数。并行工具的累计时间、模型和工具重叠时间不可相加解释为总耗时。Shell 耗时单独记录，不猜测命令是否属于测试或构建。仅保存数字和计数，不记录参数、正文、路径、凭据。

## 平台与验证

调度和计时使用 Node 标准 API，适用于 macOS、Windows、Linux；实际文件授权和修改仍由既有 Rust 实现执行。Windows 路径按大小写不敏感保守处理，macOS 也保守折叠大小写；Shell 仍与文件修改互斥。跨平台真机验证与真实模型收益不能由单元测试代替。
