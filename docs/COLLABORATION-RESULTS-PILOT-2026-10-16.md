# 围绕成果的协作体验试用

当前试用将协作 Surface 的默认内容改为本次根 Run 与其委派产生的文件变更，完整计划和委派图收进「执行详情」。保留现有入口，先验证从文件进入查看、追溯和反馈的使用路径；尚未将协作入口合并到工作区。

- 文件来源只取成功工具调用的 canonical ToolOutput，以及 Runtime 派生的 Delegation structuredResult，不从模型正文猜测产出或审查状态。
- 同一路径汇总来源；每个来源的「查看修改」沿用其已有快照，无快照时沿用当前 Git diff 回退。它不是跨 Agent 合并后的完整修改历史。
- 「打开文件」切换到现有工作区查看当前磁盘内容；历史记录里的文件可能已被移动或删除，沿用查看器的错误反馈。
- 「针对文件反馈」显式发送到当前主对话，沿用回复期间的发送队列、权限和审批；不直接给子 Agent 发消息，也不引入独立评论数据库。
- 文件变更不代表已审查、已验收或已整合。执行中的子任务尚未返回 structuredResult 时，不承诺实时显示其文件。
- 无文件任务保留执行详情与聊天正文；保存协作 Skill 仅在选中的根 Run 完成后开放。

实现仅使用现有前端、typed API 与资源导航，macOS / Windows / Linux 使用同一路径；比较路径只统一分隔符与相对前缀，不对大小写作跨平台假设。Windows/Linux 真机交互仍待验收。

后续是否融合工作区，应根据实际使用时是否能更快找到内容、理解修改来源、提出有效反馈决定，不能仅以面板展示更多信息作为成功标准。
