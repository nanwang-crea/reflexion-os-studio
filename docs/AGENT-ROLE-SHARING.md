# 角色分享

角色库的每张卡片可导出单个角色，系统目录选择器选择目标目录后生成唯一命名的 `.reflexion-role.json` 文件，不覆盖已有文件。内置角色也可分享。

角色库的「导入角色」选择该文件（最大 256KB），校验格式和版本后打开现有编辑器。检查指令、工具、权限和适用项目后保存，创建新的自定义角色；同名角色不会覆盖。未保存前不写入数据库，默认停用，模型继承上级。保存继续使用现有 Runtime 校验和权限边界。

格式为 `format: reflexion-role`、`version: 1`、`role`。role 仅包含名称、描述、指令、领域、权限上限、工具列表及是否允许继续委派；不包含 ID、执行记录、项目路径、Provider 绑定或密钥。导出拒绝疑似机密内容。接收者需要自行审阅第三方角色指令。

macOS、Windows、Linux 共用 JSON 格式、WebView 文件选择和 Tauri 系统目录选择器，Runtime 使用 node:path 与独占创建写文件。跨平台真机操作尚待验收。

## 团队批量分享

「导出团队」按现有 `team:<teamId>` 标签及精确项目范围归组，项目同名团队与跨项目同名团队分别显示。打开面板或切换团队默认全选所有成员（包括停用、未被搜索命中或未在当前页显示的角色），可逐个勾选、清空及全选。一次生成一个 `.reflexion-team.json` 文件，最多 500 个角色、4MiB。单角色文件保持兼容。

团队格式为 `format: reflexion-team`、`version: 1`、`teamId`、`roles`。每个角色沿用单角色可移植字段；移除其他团队标签，接收方仅恢复本次分享的团队关系。导入先预览全部指令、权限和工具，确认后在单个事务中创建所有角色；任一角色不合法时整包不保存。目标位置为当前查看范围对应项目或跨项目通用范围。全部新角色默认停用、继承模型；已有同名团队时分配新的团队 ID，避免混入原团队。导入包缺省的权限上限收窄为 workspace-read。
