# 模型输出预算与截断修复

本次仅修复预算、停止原因与既有循环边界，不新增继续命令或 Run 状态，不调整默认续写次数和总 token 预算。业务逻辑使用跨平台 TypeScript，macOS/Windows/Linux 采用同一机制。

- Anthropic 的实际默认输出额度与上下文预留统一为 4096。其他协议未指定额度时保留服务端默认，但上下文使用非零保守预留；预留不是模型能力声明。
- Provider 保留原始停止原因；Responses 从 response 对象读取终态和用量，不将所有 incomplete 当成长度截断；未知原因拒绝假成功。
- 正文截断保存最后片段再判续写额度；正常工具轮后连续续写归零，每次模型调用前检查总轮次。
- 长度截断区分正文、仅可见思考与完全空输出。仅可见思考进入有限恢复，和正文续写共享现有连续次数（默认 2 次），正常工具轮后归零；完全空输出停止为 output_empty。恢复不回填空 assistant 或原始思考文本，使用专门提示继续原任务，不声称恢复供应商内部推理状态。缺乏模型能力数据时不自动提高额度。
- 工具截断整批不执行，不拼接参数。最多额外请求一次，保持原额度，要求缩小参数与操作批次；重试从本轮前历史开始，既有工具结果保留。
- 上下文达到供应商边界时明确停止，现有调用前压缩仍生效；不在同样条件下反复请求。
- 每轮诊断只记录请求额度/预留、停止原因、用量及恢复次数，不包含提示词、工具参数或凭据。
- 保持 failed 终态兼容，通过细分错误码表达停止原因；重启不自动重放。截断工具草稿不注册 ToolCall，不作为合法工具轮进入历史。

验收覆盖预算一致性、供应商停止原因、空输出、混合工具截断、成功工具不重放、连续计数归零、总轮次及最后片段保留。

## Review 后修复

- Responses 工具参数事件按 item_id 关联输出 item，再映射到 call_id。added/done 事件复用同一条调用，最终 done 参数作为完整结果，不产生空调用；兼容端点直接发送 call_id 的事件。
- 续写控制消息携带内部用途标记，不依赖用户正文前缀识别。裁剪保留当前任务用户消息和续写控制消息，当前 assistant 片段采用尾部保留；标记不发送给 Provider，也不落入用户消息。
- 仅改变续写中的保留策略，不改变普通历史裁剪、预算默认值或 Run 状态。
