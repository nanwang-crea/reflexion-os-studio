# 计划模式与临时计划文档

计划模式先调研、形成可审阅的实施方案，用户批准后再执行。任务进度步骤与实施方案分开：悬浮计划卡负责进度，Markdown 文档负责完整方案，审批卡仅提供标题、文档入口与决定。

## 文档生成与审阅

`manage_plan` 先创建目标与步骤，再通过 `write_document` 提供 `planId` 和完整 `markdown`（目标、实施步骤、涉及范围、验证方式与必要取舍）。项目计划写入项目根目录 `.reflexion-studio/plans/<planId>.md`；独立会话没有项目目录，正文保存在会话计划记录中。

计划文件是临时工作文件。Rust 专用 `plan.document` 操作只接受 UUID 计划身份，不接受任意路径；普通文件写入、Shell 与 MCP 仍受计划模式限制。目录与文件符号链接拒绝，已有文件覆盖需要内容摘要，未登记文件不能覆盖。目录内生成 `.gitignore`，忽略临时文件及该 ignore 文件；不自动提交文件，也不修改项目根 `.gitignore`。

提交 `exit_plan_mode` 时读取磁盘全文，将目标、步骤规格、正文与 SHA-256 一并保存为审批快照。前端自动在右侧工作区打开文档；审批卡的“查看 / 编辑计划”打开同一文件，“查看本次审批版本”打开只读快照。用户可编辑文档或在聊天中提出修改意见。

用户编辑后，模型若需再次修改文档，应先 `get` 读取当前全文，传返回的 `document.sha256` 为 `write_document.expectedSha256`。禁止凭旧内容覆盖人工修改。

## 批准与恢复

批准时重新检查计划属于当前会话、仍 active、会话仍在计划模式、目标与步骤规格未变化、文件内容摘要与提交版本一致。文件修改、删除、不可读或旧审批没有快照时，不退出计划模式，要求重新提交审批。

审批正文保存在 `user_interactions.questions_json`，随 pending interaction 重启恢复；批准结果通过 canonical `ToolOutput` 保存完整快照，并将批准的正文回填模型，执行以该版本为依据。历史工具记录提供“查看审批时的计划”，不依赖临时文件是否存在。

## 临时文件生命周期

- 批准只开启执行，不删除文件；失败、中断、暂停与重启时保留活动计划文件。
- 计划通过 `complete_plan` 或明确 `cancel_plan` 收敛到终态后，自动清理临时文件。单次 Run 完成不等于任务完成，不能在调研 Run 收尾时误删。
- 默认仅删除系统登记且摘要仍等于最后一次系统写入的文件；人工修改的文件保留，即使用户随后批准了修改后的内容。
- 审批时可勾选“完成后保留计划文件”；也可通过 `retain_document` 设置保留偏好。取消时同样尊重偏好。
- 清理不递归删除目录，保留目录与 `.gitignore`。删除失败记录 `cleanup_pending`，下一次计划工具调用或 sidecar 就绪时重试，不改变任务成功结果。
- 已删除的干净计划预览根据工作区删除事件关闭；未保存的编辑缓冲区保留，避免丢失人工修改。
- 计划快照与审批决定按会话历史保留，删除会话时随外键级联清理。

SQLite v38 增加 `plan_documents` 登记表，由现有幂等 schema 初始化创建；不重写旧审批或历史工具结果。

## 三平台行为

macOS、Windows、Linux 均由 Rust `PathBuf` 在规范化项目根内生成路径，执行 UTF-8 文件操作；资源链接使用规范化 `/` 分隔符。文档读取、版本复核和清理不依赖 shell、POSIX 权限或信号。Windows 文件被占用等删除错误进入重试状态。符号链接测试按平台能力执行；三个目标平台仍须分别做界面和文件锁真机验收。
