# 手机会话接入与 Runtime 接入边界

## 范围与执行位置

桌面与手机连接同一个电脑 Runtime、SQLite 和 Agent。桌面保留 Tauri/stdin/stdout；
手机使用电脑按需启动的 HTTPS 服务，通过 POST 命令与 SSE 事件接入。
不以 HTTP 替换本地进程间通信。首版手机复用 ChatView、Composer、队列、审批和工具轨迹，
仅访问电脑明确配对的会话；不复制业务、数据库，不开放任意 Runtime RPC。
移动端入口与桌面入口共用前端源码，分离宿主装配；CEF 原生视图、用户终端、
Provider 密钥配置、系统文件选择和其他管理页面不属于本次手机授权范围。

## Runtime 边界

- `access/requests/` 统一 schema 校验、来源授权、handler 调用与 JSON-RPC 错误。
- EventBus 把发布与 stdout 投递分开；慢手机不能阻塞 Agent 或桌面。
- `access/remote/` 管理设备配对、HTTPS、静态资源、SSE 生命周期与会话授权。
- 手机身份是服务端设备记录，不接受客户端声明 trusted 或任意会话身份。
- 每个命令与事件都按服务端资源归属检查；配对不绕过 PermissionGate 或 Rust。
- 写命令复用 operation receipt，回执按设备命名空间隔离，移动端不自动重放写请求。
  手机不开放 Danger 开启流程；当前会话已有的 Danger 租约通过快照和事件展示，可立即关闭，
  避免手机误以为仍处于普通权限状态。

## 配对与网络

默认不监听网络。桌面在具体会话开启服务，选择本机 IPv4 地址；随机端口仅绑定
该地址（可用 loopback 做本机验证）。二维码携带短时一次性邀请，放入 URL fragment；
页面读取后移除 fragment，通过同源 JSON POST 交换待确认设备。手机显示核对码，
电脑对照后显式批准。设备凭据保存在 Secure/HttpOnly/SameSite=Strict cookie，
不进入 localStorage、日志、事件或正文；设备记录和 TLS 私钥只在进程内。
设备有期限，电脑可逐设备撤销或停止整个服务；Runtime 重启全部失效。

使用每次启动生成的自签名证书：手机首次需要在系统浏览器接受本机证书，部分
浏览器/设备策略可能禁止；UI 说明此限制。生产可信证书/公网中继留后续，
不得宣称已提供零配置可信 HTTPS 或异地访问。仅在可信且可互通的局域网使用。
不添加公网端口转发、自动防火墙规则或云端后端。

严格校验 Host、Origin、Content-Type、请求体大小、连接数、速率与命令白名单。
静态服务仅允许已构建资源清单，拒绝路径越界/符号链接/源代码与凭据。
未授权不返回会话数据；拒绝跨会话图片与附件、消息、Run、审批与问题标识。

## 同步、恢复与资源上界

SSE 建立时先在同一同步边界读取 canonical 历史、活动流式内容、待审批/问题与队列，
随后传递增量。手机重连重取快照，不假设 delta 已落库；快照和后续事件按连接顺序消费。
快照保留有界活动消息正文/思考；超出上限明确显示需要等待最终落库，禁止把截断内容
伪装成完整回复。历史分页复用 session.get。事件合帧仍采用现有 16ms 缓存。
断开不取消 Run；电脑退出/休眠则不可继续连接。无连接时不启动心跳。

## 平台与交付验证

Node HTTPS、crypto、网卡枚举和静态资源路径使用跨平台 API，不依赖 shell/openssl。
macOS / Windows / Linux 都由本机 Runtime 监听，受对应防火墙与网络策略约束。
iOS Safari / Android Chrome 需分别验证证书、扫码、软键盘、后台重连和触摸交互；
Windows/Linux 宿主与手机真机未验证前必须列为待验收。

验证覆盖：桌面请求行为回归、跨会话越权、二维码过期/单次消费、未批准设备、
撤销/过期断流、并发发送与审批、快照与流式衔接、慢连接背压、静态资源边界、
宿主断开时 HTTPS 回收、自包含打包路径、移动视口与空闲资源。

## 公网扩展边界

`RemoteEndpointProvider.open()` 返回对外 `baseUrl`、证书指纹和可等待的 `close()`；
LAN 实现负责网卡、临时 TLS 与随机监听端口，接入服务不把局域网 IP 当设备身份。
对外 URL 支持路径前缀，二维码、cookie Path、同源检查和前端相对请求均基于该 URL。
后续公网 provider 可由电脑主动建立出站隧道，提供可信 HTTPS 地址，再复用同一 HTTP
处理、设备配对、会话授权、SSE 快照及命令入口。不得因使用中继就信任任意
X-Forwarded-*、改为开放全量 RPC，或让中继读取 Provider 密钥。
公网实现还须补电脑身份认证、端到端加密、抗滥用、重连路由、协议版本兼容和中继
服务运维；这次仅交付可替换接口及路径前缀验证，不部署中继，不宣称异地访问可用。

同一设备最多两个 SSE 页面、总计最多十六个流；新页面超限明确拒绝，不反复踢掉既有页面。
静态/配对请求按来源限流，业务请求按已认证设备限流，避免未来公网中继共享出口导致全部设备共用额度。
