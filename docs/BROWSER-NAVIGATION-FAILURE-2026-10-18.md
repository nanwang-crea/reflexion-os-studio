# Agent 导航失败的浏览器面板提示

## 行为

此前 Agent 在 DNS 公网检查阶段被拒绝时，尚未申请 CEF 标签，因此不会触发“新 Agent 标签自动打开面板”，用户只能在工具轨迹看到错误。

现在工具终态落库后，Runtime 从 canonical ToolOutput 和已验证的导航参数派生可选 `tool.completed.navigation` 展示数据。前端收到当前会话（含其委派任务）的失败事件后自动打开浏览器面板，展示目标网址、导航未完成的原因和错误码。网络地址检查拒绝时标题为“导航被拦截”。

- 不创建假的 Agent 标签，不把目标网址显示成已成功加载的页面。
- 提示展示期间不附加默认网页，并隐藏旧的原生网页视图，避免盖住错误提示。
- 不重试，不自动转系统浏览器，不修改公网检查或代理配置。
- 用户可返回浏览器；重复终态事件不会重新弹出已关闭的提示。
- 当前会话后续导航成功时清除提示；切换会话时不保留另一会话的提示。

## DNS 原因（网络策略调整前的排查记录）

本次排查中，系统解析 `www.xiaohongshu.com` 得到 `198.18.0.55`。查询返回了结果，但它属于本应用拒绝的保留地址段，符合代理 Fake-IP 的特征。代理通常使用虚拟地址接管域名流量；普通浏览器在这种代理配置下仍可能正常访问，而 Agent 的公网检查会先拒绝该地址。

因此应区分 DNS 查询失败与 DNS 返回的地址不符合原公网策略。本次属于后者。同日按用户确认，浏览器已移除这项检查并使用系统网络配置，不再要求用户为应用的旧策略修改 DNS。
