# 浏览器设置与能力规划

状态：B1 实现与代码验证完成，交互及跨平台真机验收待补；B2–B3 已接入 macOS 实验实现，真机验收与下列缺口待补；B4–B5 仍为规划，2026-10-12。截图作为交互与信息架构参考，不表示截图中的功能已交付。
本规划承接 [Browser Surface](BROWSER-SURFACE.md)；用户要求后续提供网页读取与操作。

## 产品结构

设置页新增独立「浏览器」分组：常规、浏览数据、密码与自动填充、下载、网站权限、Agent 权限。
页面采用居中内容区、分组卡片、标题/说明/右侧控件布局，复用现有主题、表单、Radix 与原生对话框。
浏览器菜单中的设置、导入、密码、历史、下载入口最终跳转到对应分组；不维护两套状态。
不照搬截图中与浏览器无关的账号、计费、云电脑等页面。

## 实施顺序与验收门槛

1. **B1：设置与平台能力报告。** 先定义 Zod 设置契约、能力报告与版本迁移，再接入链接路由和设置页。
   验收重启保存、网页/本地路由、完整地址显示、不可用回退与开关关闭后的清理。
2. **B2：用户浏览基础与数据治理。** 三平台分别验证隔离存储、导航、查找/缩放/打印、持久会话与迁移。
   验收临时数据销毁、持久数据重启、分项删除、部分导入失败、密码原生验证及取消。
3. **B3：下载、网站权限和联系信息。** 原生权限拦截与文件边界先于开关开放。
   验收重定向/弹窗/子框架、权限撤销、下载取消/覆盖/路径、安全失败；不自动执行文件。
4. **B4：Agent Browser Tool。** 单独评审协议、审批、页面版本与数据流；先导航和读取，再点击/填表与下载。
   验收禁用时工具不可调用、审批撤销、跨来源重定向重新评估、陈旧页面操作拒绝、取消与审计。
5. **B5：站点工具。** 在 Browser Tool 与 MCP 安全边界稳定之后验证 WebMCP 兼容性；不是首版依赖。

每批都需要 macOS/Windows/Linux 能力矩阵与真机证据。可分平台交付，但界面必须显示实际支持状态，
不得以一个全局 enabled 掩盖平台缺口。未完成批次保留文档，不生成假开关。

## 存储与权限架构

- `contracts` 是设置、能力报告和后续权限请求 schema 的唯一真源；前端经 `api` / `runtime-client` typed facade 调用。
- 普通偏好和历史等非机密元数据由 Runtime 领域服务及 SQLite 管理；Host 只负责原生浏览器适配与可信用户命令。
  网站数据由引擎独立 store/profile 管理，原始 Cookie、密码和解密密钥始终留在原生/系统密钥存储边界。
- 用户点击设置与 Agent 工具走不同入口。Agent 必须经 ToolRegistry / PermissionGate；用户启用功能、迁移登录态
  或授予网站摄像头权限，都不构成 Agent 读取页面、使用凭据或发起远端操作的授权。
- 导航规则绑定协议、规范化 host 与端口；初版采用精确 origin，不提供模糊子串或任意正则匹配。
  公网、本地和内网网络访问明确区分；自动化不得借浏览器绕过已有网络/敏感拒读边界。
- Agent 规则绑定会话/Run、surface/tab、页面版本、origin、操作与有效期；默认 session-only，重启失效。
  如需持久规则，必须与现有权限模型一起设计迁移与撤销，不在浏览器模块另造授权体系。
- 网页正文、DOM 与站点工具描述都视为不可信内容；不执行其中要求读机密、绕过审批或隐瞒用户的指令。
  页面读取与截图须排除凭据、密码字段及其他禁止读区域，无法可靠约束的敏感场景拒绝读取。
- 提交表单、付款、发送消息等有外部影响的操作需要对应审批；一次读取授权不能覆盖写入或下载。
- 历史可能包含私有路径、查询参数和访问意图；仅在用户启用后本地保存，不写通用审计日志、不自动注入 Chat/Memory。
  审计沿用最小元数据（动作、origin、结果），不记录页面正文、完整 URL、表单值或凭据。

## 跨平台复用与待验证项

| 平台    | 浏览引擎  | 数据与凭据适配                                                              | 发布门槛                                                                |
| ------- | --------- | --------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| macOS   | WKWebView | 独立 WebsiteDataStore、应用 Keychain；现有 Chrome/Edge 迁移只支持已验证格式 | 原生权限、持久 store、打印/下载等真机验收；现阶段仅 debug Spike         |
| Windows | WebView2  | 独立 user-data folder、系统凭据保护；DPAPI/App-bound 迁移须验证系统支持     | 禁止绕过浏览器加密保护；不支持格式明确跳过，WebView2 安装与生命周期验收 |
| Linux   | WebKitGTK | 独立 WebContext/数据目录、Secret Service；无安全存储时不启用密码保存        | WebKitGTK 版本和发行版依赖、权限接口与密钥服务缺失降级验收              |

复用原生浏览引擎与成熟 UI 组件，不自行实现渲染内核、密码加密算法或网页权限补丁。
引擎提供的能力需要应用接线，不等于完整浏览器 UI 已可直接嵌入。
如果三平台原生 API 无法满足统一能力，在 B2 门槛处另行评估 CEF 的分发体积、更新、隔离和维护成本，
不为对齐截图先切换框架。

- 系统浏览器迁移的格式覆盖与平台授权能力，不能承诺所有来源和版本均能迁移。
- 截图、打印、下载在三平台上的可验证拦截方式与最低引擎版本。
- 联系信息保存是否进入首个正式发布；在密码、数据清理与权限稳定之后再开放。
- Agent 使用已登录网页时的敏感数据过滤和授权范围；上线前必须给出可测试方案。

## 提交前复审（2026-10-12）

门面串行处理。旧读取无法覆盖较新的保存结果；关闭前开始的导航先收敛，关闭后的导航
