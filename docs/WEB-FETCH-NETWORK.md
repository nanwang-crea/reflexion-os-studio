# web.fetch 网络行为

按用户决定，web.fetch 沿用 Node HTTP(S) 客户端的系统 DNS 与网络路由，不预先校验解析地址是否为公网，不固定连接 IP，也不额外发现或配置 HTTP/SOCKS 代理。系统或代理软件的透明接管（如 TUN/Fake-IP）继续由系统网络处理，工具不因 `198.18.0.0/15` 虚拟地址而提前拒绝。

本机、私网与保留地址可作为目标，域名和重定向也可到达这些地址；不承诺公网隔离或 DNS 重绑定防护。web.fetch 仍按既有权限策略自动执行，不新增审批。此决定不改变文件工具、Shell、Browser 的权限策略，也不允许读取或外传凭据。

保留 HTTP/HTTPS 协议限制、URL 用户名/密码拒绝（包括每一跳重定向）、最多五次重定向、20 秒工具超时、2 MiB 响应缓存上限和正文长度上限。网页结果继续标记为不可信外部内容。HTTPS 保留默认 TLS 证书校验。

实现位于 Runtime `network/egress/`，工具层保留正文转换与来源标记。共享 `network/address-policy.ts` 不变，不影响其他调用方。

本地回归覆盖本机 HTTP 访问、重定向、URL 凭据拒绝、协议限制、重定向上限、响应缓存上限和取消。Windows/Linux 与真实 TUN/Fake-IP 环境需分别验收；本次没有增加平台专属代码。
