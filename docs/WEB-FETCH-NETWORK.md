# web.fetch 网络出口

## 根因与行为

Fake-IP DNS 会把公网域名解析为 `198.18.0.0/15` 中的虚拟地址。旧实现只做系统 DNS 解析和公网 IP 固定连接，因此在代理环境中无法抓取公网网页。不能简单放行整个保留地址段。

网络实现在 Runtime `network/egress/`：代理发现、地址策略和 HTTP 传输分离，工具层继续负责正文转换与不可信来源标记。Browser 已使用 Chromium 系统网络；Provider 请求不在本次变更范围，不改其传输或认证行为。

每次请求（含重定向）先检查协议、URL 凭据、本机域名、常见元数据域名和私有/保留字面 IP，再选择出口：

1. 环境代理优先：`HTTPS_PROXY`、`HTTP_PROXY`、`ALL_PROXY` 及小写形式，遵守 `NO_PROXY`（使用 proxy-from-env 的标准优先级）。显式环境代理存在时，不回退系统代理。
2. 无环境代理时，读取系统手动代理和绕过列表。macOS 使用 `scutil --proxy`；Windows 使用当前用户 Internet Settings；Linux 使用 GNOME GSettings，KDE/无桌面环境通过环境变量配置。读取命令有超时和输出上限，不读取浏览器 profile 或凭据文件。
3. HTTP(S) 代理保留原始目标域名；HTTPS 经 CONNECT，保留正常 TLS 证书校验。SOCKS5 使用远端 DNS（socks5h），SOCKS4a 同样交给代理解析。
4. 无代理时，检查所有 DNS 结果，拒绝任意非公网地址，并将连接固定到已校验 IP，防止二次解析绕过。Fake-IP 返回专门诊断与配置建议。

不尝试猜测本机代理端口、不回退公共 DNS、不在代理失败后自动直连。系统 PAC/WPAD 不执行，检测到启用时明确提示设置手动代理。代理 URL 中的凭据不受支持，错误不回显代理地址。

## 代理信任边界

代理模式依赖用户配置的可信代理；允许连接本机代理端点，但不会允许将本机 IP 作为网页目标。由于实际 DNS 解析发生在代理，应用不能确认目标域名最终对应的 IP，也不能保证该域名不会指向内网；必须由代理的目的地址策略限制内网与元数据访问。直连模式保留完整公网 IP 边界。此限制不能通过本地 Fake-IP 解析可靠补足。

## Fake-IP 使用方式

开启代理软件的“系统代理”（手动 HTTP/HTTPS 或 SOCKS），应用会在下一次抓取读取；或者在启动 Runtime 前设置 `HTTPS_PROXY=http://127.0.0.1:<实际端口>`，SOCKS 可用 `ALL_PROXY=socks5h://127.0.0.1:<实际端口>`。GUI 启动会沿用现有用户 shell 环境快照机制，修改环境变量后需重启应用。

仅启用 TUN/Fake-IP、没有系统手动代理或环境代理时，仍会拒绝虚拟地址并给出明确诊断。可启用系统代理，或将需要直连校验的域名加入代理软件的 `fake-ip-filter`；不能声称仅代码更新就能自动获取未配置的代理端点。

## 验证

本地代理夹具覆盖 HTTP 原始域名、HTTPS CONNECT、SOCKS5 远端 DNS、重定向到内网拒绝、取消、环境变量优先级与 NO_PROXY、macOS/Windows 配置解析。Windows/Linux 系统配置读取及真实代理软件仍需对应平台真机验收。
