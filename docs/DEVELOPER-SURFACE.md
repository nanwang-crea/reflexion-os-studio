# 开发者页面

开发者页面是侧栏底部的独立只读页面，提供用量概览、运行记录、工具调用
及详情。它不修改权限、不重放工具，不建立额外服务或 localhost 通道。

## 数据与边界

- contracts 定义 developer.* 查询及诊断结构；Runtime 经 Store 门面查询
  SQLite；前端经 api / runtime-client，宿主使用生成的命令白名单。
- Run usage 继续作为主对话及各子 Run 的累计用量真源。新增模型调用记录
  保存每轮 usage 和上下文输入估算，独立记录 title / summary 辅助调用。
  汇总只加一次 Run usage，再加辅助调用；不重复加主调用明细或委派结果。
- 模型调用记录只保存身份、用途、时间、状态、错误码和数值诊断，不保存
  请求正文、请求头、凭据或响应正文。失败且未上报 usage 的请求保持未知。
- 工具参数和结果从现有 ToolCall / canonical ToolOutput 按需读取，详情
  不返回 approvalGrantId。列表不载入参数、结果或完整聊天内容。
- 新增工具 timing 保存审批等待、资源等待、实际调用耗时。创建到完成
  表示总历时，不能代替实际执行耗时；旧记录不推算这些阶段耗时。
- 升级是加法迁移，保留旧 usage / 工具结果；新增诊断随会话级联删除。
  进程重启把进行中的模型调用标为 interrupted，未知用量不填零。

## 统计口径

- 筛选支持时间段、项目（含独立会话）、Provider 和模型。日期边界由 UI
  以用户本地时区转为 UTC，起点包含、终点不包含。
- Run 按启动时间归属；辅助调用按自身启动时间归属。趋势按 UTC 日聚合，
  在界面中明确标注，不冒充本地自然日。
- 累计输入 / 输出 / 缓存命中按各 Provider 的现有 usage 口径展示；不把
  缓存 token 再加到输入总量，不计算跨 Provider 的统一缓存命中率或价格。
- “已报告”仅表示可观测用量，不是供应商账单。未报告、部分报告、历史
  无明细均需明确标注。失败、取消、重试 Run 仍计入已报告的实际消耗。
- 子 Run 独立计数；详情可浏览父子关系，并计算含后代的用量，不再把该
  含后代值加入全局总量。并行工作耗时相加不等于 Run 总历时。
- 上下文输入是请求构建后的估算，与 Provider usage / 累计用量分开展示。
  历史明细、未上报缓存及缺失的时间字段显示未知。

## 界面与性能

- 概览展示用量、缺失覆盖信息、日趋势、模型分布及工具成功 / 失败统计。
- Run / 工具 / 模型调用查询分页；选中 Run 后按需读取详情、子 Run、
  模型轮次和工具；可返回所属对话，保留既有工作区脏 buffer 守卫。
- 页面挂载时仅接线一次；监听完成、失败、工具终态等事件并合并刷新。
  高频正文 delta 不触发统计查询，无常驻轮询，卸载清理订阅和定时器。
- macOS / Windows / Linux 共享 React、Node SQLite 与 Tauri 通道；
  下拉使用共享 Radix Select，无新增 OS 依赖；真机验收分别记录。

## 代码审查与修复（2026-10-22）

以下问题均先以回归测试复现，再完成修复：

- 诊断通知异常会阻止模型请求，或把成功调用改为失败；现在通知失败仅写
  固定诊断日志，不影响业务结果。模型失败后的诊断落盘异常保留原始错误。
- 工具结束后的可选耗时写入失败会遮蔽已完成的操作，导致 canonical 结果
  无法保存；耗时采集改为尽力写入。无效/未知版本的 timing 只投影为未知，
  不再阻断工具历史读取，权限及 canonical 结果持久化保持原有边界。
- 查询耗时超过刷新间隔时，旧实现会不断丢弃尚未完成的结果；现在同一
  查询只保留一个进行中的请求，并合并一次后续刷新；筛选变化仍丢弃旧结果。
- 查看详情后返回会丢失分页、工具筛选和 Run 详情分类；现在保留这些组件
  的局部状态，隐藏内容暂停新查询，返回时刷新当前页。

新增 4 项 Runtime 故障回归、2 项页面回归通过。最终完整回归：Runtime

格式、lint、根级与前端 typecheck、白名单一致性、TS 构建、宿主 check
