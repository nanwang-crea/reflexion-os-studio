# 集成终端设计：项目级多标签用户终端（xterm + portable-pty）

> 日期：2026-09-12。状态：已评审（brainstorming 流程产出，两轮修订）。
> 上游文档：[ARCHITECTURE.md](../../../ARCHITECTURE.md)、[ROADMAP.md](../../ROADMAP.md)。
> 评审期间对现有代码的核实结论：
>
> - `SystemRuntimeClient.handleLine`（apps/runtime/src/system.ts）当前只处理 `system.ready`
>   与 pending 请求响应，其余通知静默丢弃——PTY 通知路由是必须补齐的缺口。
> - Tauri 命令白名单由契约生成（`scripts/generate-runtime-methods.mjs` →
>   `packages/contracts/generated/runtime-methods.json` → OUT_DIR `runtime_methods.rs`），
>   新命令只改契约，不手改生成物。
> - `run_events` 表持久化的是域类型 `RunEvent`（结构化列，仅 retrying/failed），
>   **不是**线格式 `RuntimeEvent` 信封——信封泛化（§7）不触及任何已落库数据，无需迁移。

## 1. 目标与范围

为桌面端增加项目级、多标签、跨页面保活的**用户终端**（Terminal Surface）。

技术选型：`@xterm/xterm`、`@xterm/addon-fit`、Rust `portable-pty`；沿用现有 stdio
JSON-RPC 链路，不使用 PTY 插件、不引入本地 HTTP/WebSocket 服务。

首版支持：

- 创建多个独立终端、切换标签。
- 交互输入、持续输出、复制粘贴、Ctrl+C、调整尺寸。
- 切换聊天、设置等页面及项目后，终端保持运行。
- 关闭、退出状态展示、重新创建。
- 应用退出和异常情况下的受管理进程回收。

首版不做：OSC 133 shell integration、Agent 接管、SSH/串口管理、自定义 shell 配置
（Git Bash / WSL 不纳入保证范围）、跨应用重启恢复、输出持久化、WebGL 渲染器。

## 2. 产品行为

终端面板位于主工作区底部，可收起、调整高度；右侧文件查看器保持独立。

| 场景                 | 行为                                                       |
| -------------------- | ---------------------------------------------------------- |
| 创建终端             | 当前项目 workspace 为初始目录；每个标签独立 shell          |
| 无项目 workspace     | 不允许创建，不默认使用用户主目录                           |
| 切换标签、页面、聊天 | 保留进程、xterm 实例、输出和选中项                         |
| 收起面板             | 仅隐藏，继续消费输出，停止尺寸测量                         |
| 切换项目             | 展示对应项目标签，其他项目终端继续运行                     |
| shell 自然退出       | 保留只读画面和退出信息，可重新创建                         |
| 关闭活跃标签         | 确认后回收对应终端，释放实例和资源                         |
| 删除项目             | 有活跃终端时确认；完成回收后才删除项目                     |
| 退出应用             | 统一回收全部终端                                           |
| Runtime 重启         | 原标签显示"已断开"，禁止输入，不自动重跑命令               |

- "重新创建"使用原项目的初始目录和默认 shell，**不声称**恢复上次工作目录、环境或命令。
- 首次创建提示：`终端使用当前用户权限运行。项目目录只是起始目录，不限制访问其他文件。`
- 未实现 shell integration，不能可靠判断 shell 空闲还是执行中。关闭确认统一为
  "关闭终端将终止 shell 及其子进程"，不展示未经验证的命令状态。
- 跨页面保活针对正常应用导航。前端整页刷新、WebView 崩溃、应用重启后的完整画面
  恢复不纳入首版承诺（与普通页面切换是不同场景）。

## 3. 与 Agent 的权限边界

用户终端与 Agent 执行工具完全独立：

- Agent 继续使用现有受审批控制的 `shell.execute`。
- 不向 Agent 工具注册表注册任何 `terminal.*` 命令。
- 用户打开终端不产生任何 Agent 授权。
- 终端输入输出不自动进入对话、上下文、记忆、日志或执行轨迹。
- Chat Stop 只停止 Agent Run，不关闭用户终端。
- 不把 Agent 工具执行结果伪装成"在某个用户终端里运行"。

后续若增加"发送选中文本给 Agent"，必须为用户显式触发；"Agent 接管终端"另行设计
明确授权、输入归属与审计记录。

## 4. 架构与职责

```text
应用级终端管理器 / xterm 面板
             ↓
前端 api → runtime-client
             ↓
Tauri 白名单转发（runtime_request / bootstrap:message）
             ↓
TS Runtime 终端服务
             ↓
Rust System Runtime PTY 服务（portable-pty）
             ↓
本机 shell
```

| 层                | 职责                                                       |
| ----------------- | ---------------------------------------------------------- |
| 前端              | 标签、展示状态、xterm 实例、输入批处理、消费确认、resize   |
| TS Runtime        | 项目归属、终端元数据、幂等、资源额度、事件路由、输出公平调度 |
| Rust System Runtime | PTY、shell、输入队列、输出缓冲、进程生命周期             |
| Tauri Host        | 协议转发和进程树兜底监管，不承载终端业务                   |

三个所有权必须分清：Rust 拥有 PTY/shell/读写句柄/受管理进程；TS Runtime 拥有
`projectId → terminalId` 映射、生命周期与资源限额；前端拥有标签、选中项、xterm
实例与面板状态。

- **终端实例宿主必须位于页面条件渲染之外**；导航仅切换可见性，不卸载重建实例、
  不发送关闭请求。
- 输出直接写入 xterm，React 只维护低频的标签和状态。禁止同时在 React state、
  Runtime 缓存和 xterm 中保存三份完整输出。
- 依赖版本在 W1 贯通验证后固定；首版使用 xterm 默认渲染器，不启用 WebGL。

## 5. 契约与状态机

全部契约在 `packages/contracts` 用 zod 定义，TS 类型与协议产物（白名单清单等）
从契约派生。

### 命令

| 命令            | 语义                                       |
| --------------- | ------------------------------------------ |
| terminal.create | 使用调用方幂等 ID 创建终端，返回元数据     |
| terminal.list   | 查询项目终端及状态                         |
| terminal.attach | 绑定输出消费者，允许开始输出               |
| terminal.write  | 接收带序号的输入批次                       |
| terminal.resize | 更新行列，Runtime 侧保留最新尺寸（可合并） |
| terminal.ack    | 累计确认已消费输出，释放额度               |
| terminal.close  | 幂等关闭，完成回收后响应                   |

事件：`terminal.output`、`terminal.state`。

元数据至少包括：terminalId、projectId、初始目录、shell、尺寸、状态、退出信息、
Runtime 代际。初始目录不命名为"当前目录"。每项操作校验项目归属。

### 状态机

```text
starting → running → closing → closed
               ├→ exited
               └→ disconnected
starting → failed
```

规则：**任何非终态遇到 Runtime（TS 或 Rust sidecar）代际变更一律进入
`disconnected`**，不限于 running。closed 标签不长期保留；只保留必要的短期幂等
记录（含 TTL），不占保留标签额度之外的名额。

### 输入路径

保留现有请求/响应通道，但不逐键等待响应：

- 普通输入在前端短窗口内合并成批；粘贴按字节上限分块。
- 每终端有界在途窗口，服务端按输入序号串行入队。
- write 响应表示"已接收入队"，不表示命令执行完成。
- 重复序号不重复写入；乱序、超量或终端已关闭时明确拒绝。
- 在途窗口满后前端停止提交后续批次，不允许无限积压。
- 未知是否已写入的输入不自动重发（避免重复执行）；提示输入状态不确定。
- close 不等待输入队列排空。
- 粘贴前检查整体大小，超限整段拒绝并提示，避免静默截断形成意外命令。

### 创建与 attach

1. Rust 先建立有界输出缓冲，再启动 shell。
2. 前端收到 create 结果后准备 xterm，再 attach。
3. attach 前输出进入有界缓冲；达到缓冲上限暂停 PTY 读取，不丢弃。
4. attach 后从第一字节按序交付，保留启动横幅。
5. create 返回后 10 秒内未 attach：超时关闭终端、**释放活跃终端额度**、
   回收 PTY 并发布 `terminal.state`（failed/closed），不允许僵尸终端占名额。
6. 创建超时后的查询或重试沿用同一幂等 ID，绝不直接再建一个 shell。

## 6. 输出、历史与背压

三类数据严格分离：

| 数据           | 归属                                              |
| -------------- | ------------------------------------------------- |
| 滚动历史       | xterm：`scrollback: 5000`，屏幕行另计             |
| 未消费字节     | Rust 与传输层的**有界未交付缓冲**，仅用于按序交付 |
| 断开后的画面   | 保留原 xterm 实例，只读展示                       |

"Runtime 不保存第二份历史、不提供历史回放接口"与 §5 的 attach 前缓冲不冲突：
后者是有限字节的交付缓冲（attach 即清空转正式流），不是可查询的滚动历史。

输出机制：

- 原始字节以 base64 跨 JSON-RPC，前端还原为 `Uint8Array` 直接喂 xterm。
- 约 16ms 或字节上限合帧。
- 每帧携带终端内输出序号、Runtime 代际、消费者代际；旧代际事件丢弃，
  不进入新实例。
- xterm 写入完成后批量 ACK（累计确认，重复 ACK 不重复释放额度）。
- 未确认字节达到窗口上限后暂停 PTY 读取，不丢字符流。
- 正常退出先交付尾部输出，再发布 exited 事件。
- 异常断开允许尾部丢失，但必须明确显示 disconnected 状态。
- 隐藏的终端继续解析输出，但不做 fit、尺寸测量或周期性布局。

### 资源预算（实施初值，W1/W4 压测校准，不是已验证的性能结论）

| 项目               | 初值                             |
| ------------------ | -------------------------------- |
| 每项目活跃终端     | 8 个                             |
| 全应用活跃终端     | 16 个                            |
| 全应用保留标签     | 32 个（含已退出标签）            |
| 单输出帧           | ≤16 KiB 原始字节                 |
| 每终端未确认输出   | ≤256 KiB                         |
| 单输入批次         | ≤8 KiB                           |
| 每终端在途输入     | ≤4 批，同时受总字节额度约束      |
| 单次粘贴           | ≤1 MiB                           |

达到活跃标签上限时提示用户关闭旧标签，不自动删除任何标签。

### 共享通道保护

所有 runtime→UI 消息共用 supervisor 单线程逐行解析 + `app.emit` 转发链
（supervisor.rs），终端输出与 `message.delta` 竞争同一跳：

- 应用级终端输出总额 ≤1 MiB/s（按实际 JSON 帧体积、含 base64 膨胀计算）。
- 多终端公平分配发送机会，单个高输出终端不能长期占满共享通道。
- Chat、审批、Stop、输入、ACK、close 等控制消息优先于输出数据。
- TS 与 Rust 的**所有**发送队列有界，不能只限制 PTY 侧队列。
- 额度在发送前扣减；已进入宿主管道的数据不能被后来的消息抢占。
- 后台高输出程序最终可能被背压阻塞——这是明确的保护行为，不承诺后台命令
  永远不受输出速度影响。

首版不重构为独立高速传输通道；若现有通道无法满足 §10 验收，回到设计层单独
评审传输方案，不在交付时临时放宽门槛。

## 7. 事件信封泛化（W0，独立工作包先行）

不再继续借用 `runId`（workspace/queue/mcp 已有三次借用先例，本次是第四次，
到此为止）。信封改为显式 scope 的 zod 判别联合，不采用"一堆可选 ID"：

```text
run      → runId
project  → projectId            （workspace.index.*）
session  → sessionId            （queue.changed 等）
terminal → projectId + terminalId
runtime  → 无额外资源字段
mcp      → serverId
```

要求：

- 盘点并迁移所有生产者、消费者、事件排序与去重逻辑；`RunEventEmitter` 的
  run 假设拆出通用资源事件发射器。
- 明确 `seq` 所属事件流（run 流内单调）；终端字节序另用输出序号，不混用。
- 同步更新 `PROTOCOL_VERSION` 与握手校验；开发态版本不匹配必须明确失败或
  降级，不允许静默兼容。
- TS Runtime、前端与 Rust sidecar 随安装包整体升级。
- Tauri 白名单从契约生成源更新，不手改生成物。
- 存储侧已核实：`run_events` 只存域类型 `RunEvent`，不含线格式信封，
  无需数据迁移（见文档头部核实结论）。

## 8. 三平台执行与关停

| 平台            | 默认 shell                        | 生命周期处理                                       |
| --------------- | --------------------------------- | -------------------------------------------------- |
| macOS / Linux   | 有效用户 shell，回退 `/bin/sh`    | PTY 会话、前后台进程组及受管理后代回收             |
| Windows         | 优先 `pwsh.exe`，回退 `powershell.exe` | ConPTY；验证 Job Object 等进程约束方案         |

- 启动使用路径 + 独立参数数组，不拼接命令字符串。
- Unix 交互 shell 有作业控制，不能只杀 shell PID 或单个进程组就声称完整回收。
- Windows 不能用 Unix 信号模拟关停，也不能只依赖 shell 自身退出。
- 不复用批处理式 `shell.execute` 的生命周期实现。
- 协议 shutdown、stdin EOF、TS 崩溃、Rust 异常退出都必须触发清理；Host 继续
  承担进程树兜底监管。
- 验收承诺只针对应用拥有和约束的进程树；用户主动脱离终端（disown/setsid）、
  启动系统服务等行为不承诺全部收回。

### 关停预算

- shutdown 开始即禁止新建与输入，解除输出等待。
- 全部终端**并行**回收，不逐个等待。
- 正常回收以 1 秒为目标，剩余宽限用于强制回收，必须在 TS 现有 2 秒协议关停
  预算（`SHUTDOWN_GRACE_MS`）内收敛。
- Host 3 秒兜底 kill 树保留，但不是正常关闭路径。
- 回收失败不得假装成功：如实上报状态；项目删除失败时保留项目并提示。

## 10. 实施、验收与回滚

### 实施顺序

1. **W0**：文档 + 信封泛化——旧事件、握手、生成链回归通过。
2. **W1**：三平台贯通验证——PTY、默认 shell、交互程序、回收、WebView 行为
   （含隐藏窗口下 xterm 消费与定时器节流）；固定依赖版本与性能门槛。
3. **W2**：后端多会话服务——幂等、输入序号、输出背压、额度与公平调度。
4. **W3**：前端多标签与保活——应用级实例宿主、导航切换、状态展示、resize。
5. **W4**：故障、性能、打包验收。

### 必测清单

- 多终端并行、切换全部页面和项目：不重建实例、不丢输出、不重复订阅。
- 中文、emoji、跨帧边界的 UTF-8、复制粘贴、Ctrl+C、交互程序（vim/top）、resize。
- create→attach 竞态、attach 超时释放额度、创建超时后同幂等 ID 重试、重复关闭、
  退出与关闭竞态、旧代际事件丢弃、重复/乱序输入序号。
- 16 个终端同时持续输出（如 `yes`）时：其他终端、Agent 流式回复、审批、Stop
  仍可用。
- 16 个终端并行关停、含持续输出与忽略优雅关闭的进程：2 秒内收敛、无受管理
  进程残留（`pgrep -fl` 验证）。
- 关闭标签、项目删除、正常退出、Runtime 崩溃后的进程回收。
- 空闲 CPU ≈0（AGENTS §10 方法），持续压力下内存与队列有界。
- AGENTS.md 完整验证链 + 打包冒烟；Windows/Linux 在对应环境实际验收，
  未验证项如实标注，不宣称三平台完成。

### 性能门槛（W1 固定，交付时不得放宽）

- UI 消费至展示的聊天 delta 延迟：p95 ≤100ms，且相对无压力基线增量 ≤50ms。
- 测试控制命令响应：p95 ≤300ms。
- 持续输出 10 分钟：队列不突破额度、内存无持续线性增长。
- 使用可重复的测试 Provider（录制回放）与事件时间戳，隔离模型网络波动。

### 发布与回滚

入口开关可禁用新建终端；回滚前统一关闭已有终端；无数据库回滚负担。
