## 设置页整体视觉优化方案

### 1. 重整页面层级与布局
- 以 `SettingsView` 作为唯一页面标题层，保留一次“设置”和页面说明，移除各子面板重复的 h2/说明文案。
- 顶部改成清晰的工具栏：返回对话作为次级操作，刷新作为图标按钮；页面标题与操作在宽窄窗口下都保持稳定对齐。
- 设置分类导航保留左侧结构，但改成更轻量的分组导航卡，不再使用厚重的半透明嵌套表面；宽屏居中并限制内容最大宽度。
- 小于约 900–1000px 时，将左侧导航转换为横向可滚动 tabs，避免窄窗口把右侧内容压缩到不可用。

### 2. 统一视觉 token 与表面层级
- 在 `features/settings/settings.css` 内建立设置页专属的颜色、边框、圆角、间距和阴影变量，统一 Provider、Agent、MCP 的卡片外观。
- 减少“黑色卡片套黑色卡片”的层级：页面背景、导航面板、内容卡片只保留 2–3 个明确层级。
- 统一控件高度、输入框 padding、按钮层级（primary / secondary / ghost / danger），并为设置页控件增加一致的 focus ring 和 hover/active 状态。
- 对设置页选择器做命名空间约束（优先使用 `.settings-view ...`），避免全局导入 settings.css 污染其他页面的 `.field`、`.hint`、`.form-actions` 等通用类。

### 3. 优化模型供应商页面
- 保持 ProviderList + ProviderEditor 的功能结构，但明确“列表区 / 编辑区”两个区域，减少无意义留白。
- 为编辑表单增加分组标题与分隔：基本信息、模型、采样参数、凭据/操作；模型行使用更清晰的行容器和删除操作。
- 让编辑内容使用合理的最大宽度，操作区固定在底部或保持明显的主按钮层级。
- Provider 管理器在窄屏下改为纵向堆叠，并避免产生多层独立滚动区域。

### 4. 优化 Agent 运行时面板
- `AgentRuntimePanel` 取消重复标题和说明，只保留内容主体；四个设置项按“执行控制 / 失败处理 / 网络请求”分组。
- 使用自适应网格（`auto-fit/minmax`）适配窄窗口，避免固定两列挤压。
- 每个字段保留显式 label 和短辅助说明，降低大段 hint 造成的视觉噪声。
- 保存区改为明确的 primary button，并为成功/失败信息预留稳定位置，避免布局跳动；错误状态提供可见但不抢夺主视觉的样式。

### 5. 优化 MCP 页面
- 新增服务器表单改成显式 label 的两行/响应式布局，不再依赖 placeholder 充当说明。
- MCP 列表项拆成“名称 + 状态”“命令”“错误/工具”“操作”几个视觉行，使用统一 status badge 区分 connected/failed/stopped 等状态。
- 空状态增加说明和明确的添加入口；操作按钮区分启动、停止、重连和删除的优先级。

### 6. 验证与 review
- 只修改前端 settings feature 组件和样式，不改变 Runtime/API 行为。
- 运行 `pnpm format:check`、`pnpm lint`、根级 typecheck、Desktop typecheck 和前端构建。
- 通过浏览器黑盒打开设置页，分别检查模型供应商、Agent 运行时、MCP 三个区块，以及窄窗口响应式、键盘 focus 和加载/错误状态。
- 最后检查 diff，重点 review 是否引入全局 CSS 污染、嵌套滚动、功能回归或不符合现有设计语言的问题。
