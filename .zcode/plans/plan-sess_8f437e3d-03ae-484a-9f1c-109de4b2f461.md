## 目标

一次推进到 MVP 可用闭环：**M2 Runtime Chat Core + M4 SQLite 存储 + M3 最小 UI**。满足你定义的 Key 交互：无 Key 时应用正常可用并在发送/启动时提示，用户自行进入配置页完成 Provider 配置后再使用 Chat。

## 1. 契约扩展（packages/contracts，增量变更，协议版本不变）

- `provider.configure` params 增加**只写**字段 `secret`（明文 Key 仅此单向出现，永不回传、不进日志/事件/响应）；runtime 存入本地 secret 文件并返回 `secretRef`。
- `session.get` result 扩展为 `{ session, messages, runs }`（UI 恢复历史所需，文档未禁止的增量）。
- 补测试：secret 参数、session.get 结果结构。

## 2. M4 存储（apps/runtime，零原生依赖）

- 用 Node 22 内置 `node:sqlite`（DatabaseSync，同步，单写者）。不引入 better-sqlite3。
- 数据目录：`REFLEXION_DATA_DIR` ?? `~/.reflexion-os-studio`；`reflexion.db` + `secrets.json`（0600 权限）。
- 表结构按 MVP-DATA-MODEL，另加 `runs.retry_of_run_id`（同步更新该文档）；外键开启、WAL。
- 启动恢复：`created/running` Run → `interrupted`，`pending/streaming` Message → `interrupted`（保留 partial 内容）。
- 完成时单事务写完整 Assistant Message + Run 终态；异常/取消时单事务写已累积内容 + interrupted/failed。

## 3. M2 Chat Core（apps/runtime 模块化拆分）

- `store.ts`（存储）、`secrets.ts`（本地 secret 文件）、`provider.ts`（OpenAI-compatible SSE：fetch 流式解析 delta/finishReason/usage、AbortSignal、120s 超时、错误映射 401→authentication、429→rate_limit、404→configuration、5xx→provider、网络→network）、`events.ts`（事件信封：run 内 seq 递增 + eventId/occurredAt）、`agent.ts`（Primary Agent 编排）、`handlers.ts`（11 个命令实现）、`index.ts` 瘦身为传输循环。
- 全部命令落地：project/session CRUD、message.send（建 user/assistant 消息 + Run → 流式 delta → 事务终态）、run.cancel（AbortController，幂等，竞态先提交者生效）、run.retry（新 Run + retryOfRunId，保留原 Run）、provider.list/configure。
- 会话上下文 = system prompt + 会话全部历史；MVP 不做截断策略（记录为已知限制）。不自动重试，仅手动 Retry。
- 无已启用 Provider 时 message.send 返回稳定错误 `configuration`，前端据此提示。

## 4. Host 桥接（src-tauri）

- 新增白名单 command `runtime_request(method, params) -> id`：仅允许 11 个 MVP 方法，复用 request_seq，写 runtime stdin 并把 id 返回给前端；响应仍经 `bootstrap:message` 事件透传。前端自行按 id 关联（Host 保持无状态）。

## 5. runtime-client（首次实现真实代码）

- `RuntimeTransport`：`request(method, params)` 按 id 关联响应（Promise + 超时）、`onRuntimeEvent(handler)` 过滤 runtime 通知、监听器共享支持并发请求；依赖注入 listen/invoke 便于测试。

## 6. M3 最小 UI（React + Vite，遵循架构文档技术选型）

- desktop 增加 react/react-dom/@vitejs/plugin-react 依赖与 JSX tsconfig。
- 页面：左侧 Project/Session 侧栏（列表 + 新建）；主区 Chat（消息气泡、流式渲染、Stop、失败/中断消息的 Retry）；顶部状态徽标（沿用 bootstrap 状态）。
- **Provider 配置页**（设置视图）：profile 列表 + 表单（name/baseUrl/model/API Key/enabled），Key 保存后只显示"已配置"；无已启用 profile 时聊天区顶部显示"未配置 API Key"提示条 + 跳转按钮，发送按钮禁用并说明原因。
- runtime-client 作为前端唯一访问通道（架构红线）。

## 7. 测试与冒烟

- runtime 新增 node:test：store（CRUD/事务/恢复）、provider SSE 解析与错误映射（本地 mock SSE server）。
- `scripts/mock-provider.mjs` + `scripts/smoke-chat.sh`：无 Key 的端到端验证——mock OpenAI SSE 服务 + 临时数据目录，走 configure → message.send → delta → completed 全链路。
- 扩展 smoke-protocol.sh 覆盖新命令与 secret 写入。
- test-all.sh 挂入 runtime 测试。
